# Li Auto Monitor

Flutter-приложение для проверки **сетевого доступа с текущего устройства** к адресам Li Auto. Проверка не выполняется из автомобиля и не подтверждает авторизацию владельца, выполнение команд, получение прошивки или исправность автомобиля.

## Как выполняется проверка

1. DNS разрешает имя один раз. Проверка сохраняет список адресов и ограничивает время ожидания.
2. Устанавливается TCP-соединение с конкретным адресом. При ошибке допускается следующая попытка с другим адресом из того же DNS-ответа. Фактический IP и семейство IPv4/IPv6 сохраняются в результате.
3. На этом же соединении HttpClient выполняет TLS с исходным именем домена: проверяются сертификат и имя сервера. Проверка сертификатов не отключается.
4. По тому же соединению отправляется `HEAD /`. Читаются заголовки; перенаправления автоматически не выполняются. Тело ответа не нужно.

Это проверка прямого соединения. HTTP-прокси не используется. Маршрутизация устройства, включая VPN, может влиять на результат.

Все этапы одной попытки относятся к одному IP. В отчёте остаются результаты предыдущих неудачных попыток. Полученный HTTP-ответ, в том числе ошибочный, не скрывается поиском другого IP с более удобным кодом.

## Значение результатов

| Результат | Отображение |
|---|---|
| HTTP 2xx | Адрес доступен по сети; функции автомобиля не проверены |
| HTTP 3xx | Перенаправление; конечный адрес не проверен |
| HTTP 401/403 | HTTPS доступен; нужна авторизация или запрос отклонён |
| HTTP 404/405 | HTTPS доступен; корневой адрес или метод HEAD не подходит для проверки функции |
| HTTP 429 | Сервер ограничивает запросы |
| HTTP 5xx | Сервер ответил ошибкой; жёлтое предупреждение |
| Ошибка DNS/TCP/TLS | Соответствующее соединение не установлено |
| Этап после неудачного предыдущего | «Не выполнялось», а не ошибка |
| Нет завершённого измерения | «Нет данных», а не зелёный статус |

`online` означает успешный сетевой запрос; `degraded` — защищённое соединение установлено, но HTTP-ответ или отсутствие ответа требует внимания; `down` — DNS/TCP/TLS не завершён. Никакое из этих состояний не доказывает исправность или неисправность самого автомобиля.

Контрольные адреса помогают получить дополнительные свидетельства доступа. Их недоступность не является доказательством отсутствия всего интернета. Положительный результат TLS до Li Auto учитывается, даже когда внешние контрольные адреса не отвечают.

В `lib/config/hosts_config.dart` адреса `OTA Test` и `OTA OnTest` явно отмечены как дополнительные. Их результаты видны, но не определяют общий вывод по основным адресам. Это конфигурация приложения, а не подтверждённый официальный перечень зависимостей Li Auto.

## Мониторинг и остановка

Одновременно работают не более трёх проверок адресов. Повторное обновление присоединяется к текущему циклу. Новый автоматический цикл начинается через 30 секунд после завершения предыдущего. Лимит одного адреса — 15 секунд, одного ожидания — до 4 секунд, цикла — 60 секунд.

При паузе, уходе приложения в фон или уничтожении сервиса отменяются операции, закрываются сокеты и HTTP-клиенты. Поздние результаты отменённых операций не применяются к экрану или истории. Сам системный DNS-запрос может завершиться позже: Dart не предоставляет его принудительную отмену, поэтому его результат игнорируется.

GeoIP — необязательная справочная информация с отдельным общим лимитом времени. Ошибки GeoIP не меняют сетевой статус. Приватные и локальные адреса не отправляются на GeoIP-сервис.

## История

История хранит состояния `online`, `degraded` и `down` раздельно, а также границы подтверждённых интервалов и идентификатор сессии мониторинга.

Предыдущее состояние переносится только до следующего измерения той же сессии, если промежуток не превышает 90 секунд. Это оценка состояния между измерениями, а не непрерывное измерение каждой секунды. Один образец не даёт ненулевой длительности наблюдения.

Время после последнего измерения, большие разрывы и промежутки между сессиями отображаются серым: «Нет данных». Процент сетевой доступности считается только по наблюдавшимся интервалам; рядом выводится покрытие выбранного периода измерениями. Жёлтые интервалы сохраняются отдельно и означают, что TLS-соединение было установлено, но HTTP-результат требовал внимания.

Файл `monitor_history.v2.json` содержит версию схемы. Записи уплотняются по состоянию и сохраняются не реже пяти минут при наличии изменений, а также при сменах состояния и явной остановке. Операции записи последовательные; временный файл и резервная копия позволяют восстановиться после прерывания замены файла. При принудительном завершении процесса последние несохранённые наблюдения могут отсутствовать.

Старый `monitor_history.json` читается без выдумывания непрерывности: у старых точек нет подтверждённых интервалов, поэтому они не превращаются в ночной uptime.

## Маршрут

Трассировка запускается отдельной кнопкой. Это **ICMP с изменением TTL**, а не TCP SYN traceroute. Используется один выбранный IP, результат обычной проверки не перезаписывает маршрут.

Отсутствие ответа промежуточного узла не доказывает потерю пользовательского трафика, блокировку или её местоположение. GeoIP не используется для определения виновника сетевой проблемы.

Текущий адаптер `dart_ping` 9.x ограничен возможностями платформы; в этой реализации ICMP-трассировка IPv6 не выполняется и сообщается как неподдерживаемая. Основная HTTPS-проверка поддерживает IPv4/IPv6. Отсутствие ICMP-поддержки на платформе не делает HTTPS-сервис недоступным.

## Разработка и проверка

```bash
flutter pub get
flutter analyze
flutter test --reporter expanded
flutter run
```

Сетевые регрессионные тесты создают локальный HTTPS-сервер и временный тестовый сертификат с помощью `openssl`. Они не обращаются к Li Auto. Проверяются HTTP-коды, проверка имени сертификата, выбранный IP, резервный IPv4-адрес, таймауты DNS/TLS/HTTP и отмена операций. Отдельные тесты проверяют историю, покрытие, восстановление файла, совместный цикл обновления и отображение непроверенных этапов.
